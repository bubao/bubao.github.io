代码即图形：纯代码生成多平台图标

本文介绍如何利用解析几何与 SVG 纯代码构造矢量母版，解决莫比乌斯环互锁死锁，并一键无损衍生全套跨平台原生图标资产。

在跨平台桌面与 Web 开发中，为软件准备全套图标往往是一项繁琐且极易出错的手工作业。不同操作系统对图标格式和渲染规范的要求碎片化极其严重：

  • macOS：要求生成包含 10 档分辨率（从 16×16 至 512×512@2x）的 .iconset，并封装为苹果专用的 .icns 格式，且必须遵守严苛的连续曲率超椭圆（Squircle）与边缘透明通道；
  • Windows：要求内嵌 16/32/48/64/128/256px 多个分辨率图层的标准 .ico 复合二进制文件；
  • Linux：需提供遵循 XDG 规范的 256×256 透明底 PNG 与配套的 .desktop 快捷方式描述；
  • Web 端：需要适配明暗双色模式的高保真矢量 favicon.svg。

传统的做法依赖设计师在 Figma 或 Illustrator 中手工绘制、肉眼调整，再一张张切图导出。然而，一旦需要微调颜色饱和度、圆角弧度或镜头几何比例，整套繁重的导出流程就必须全部推倒重来。

在开源博客工具 hpic 的开发中，我们践行了 “代码即图形（Code-as-Graphic）” 的设计范式：抛弃静态设计图，将数学解析几何公式作为图形的单一事实源（Single Source of Truth, SSOT），不仅攻克了莫比乌斯环互锁难题，还实现了一键秒级自动化派生全平台图标。

二、几何拓扑破局：三层解耦解决莫比乌斯环死锁

hpic 的品牌图标由六瓣顺时针排布的彩色快门叶片环形互锁而成。这种首尾相接的圆环拓扑，在传统 2D 绘图软件中必然会遭遇 Z-Index 拓扑死锁（Topological Deadlock）：

如果叶片 1 压在叶片 2 上，叶片 2 压在 3 上……到最后一片叶片 6 时，按图层顺序它在最顶层，但几何上它必须被第一片压住。传统的二维图层堆叠无法表达这种莫比乌斯环互锁关系。

为了从根本上消除图层死锁与手动绘图容易出现的发丝缝隙，我们设计了三层解耦数学算法：

1. 基底扇区（Base）

定义每块叶片的基底只覆盖精确的 $60^\circ$ 扇形圆环。6 块基底在同一平面顺时针拼合，恰好 $6 \times 60^\circ = 360^\circ$ 密闭铺满大圆环，彼此平级，互不重叠覆盖：

2. 顶层搭接（Flap）

在基底上方绘制第二层搭接瓣：

  • 向内侧回缩延伸，完全融合同色基底，消灭浮点数渲染计算误差带来的发丝细缝；
  • 向外侧越过扇区边界延伸，顺延压在下一瓣的主体上；
  • 此时各瓣搭接关系彼此对称独立，完全绕开了“谁在谁最底层”的全局死锁。

3. 接触羽化阴影（Shadow）

在交界线处定义一条带有微渐变透明度的投影带（宽度 24px，起始透明度 0.22 逐步平滑渐变为 0）。通过解析几何计算，6 条阴影的长度、宽度和衰减曲线绝对均匀对称，彻底消除了手工修图容易产生的阴影浓淡不均和脏斑感。

三、三阶物理漫反射底托（Elevation Shadow）

为了让图标在浅色、深色系统壁纸上都具备极强的悬浮感，底托卡片没有采用单一直白的投影，而是构建了三阶光学漫反射投影栈：

配合外围的纯白超椭圆卡片（Squircle Card），在任何背景上都能呈现出层次分明的立体悬浮质感。

五、总结与工程价值

将“视觉设计”转变为“确定性代码”带来了三大核心红利：

  1. 版本化与可审计：图标的半径、旋转角度与色值变更是标准的 Git Diff 文本代码，再也不用在 Git 仓库里反复提交大体积二进制 PSD/Figma 资产；
  2. 免工具依赖与零偏差：新机器克隆代码后，无需打开任何商业设计软件，只需执行一条 node scripts/build-icons.mjs，所有端（Web / macOS / Windows / Linux）的专属格式瞬间刷新；
  3. 极高几何精度：用三角函数与解析几何取代鼠标拖拽微调，从根源上杜绝了非整数像素与微小位移带来的模糊与毛刺。
