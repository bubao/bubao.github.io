Express 项目环境搭建 -- 11. 连接 Sqlite

Express 有第三方连接数据库的中间件，但因为中间件使用的是依赖注入，就没有编辑器提示，所以更好的方式是使用单例模式，引入模块的方式来实现 Express 连接数据库。

Node.js 从 22.5 开始内置了 node:sqlite 模块，不需要安装第三方依赖就能操作 SQLite，这里就用它来连接 SQLite。

node:sqlite

node:sqlite 是 Node.js 内置的 SQLite 绑定，底层就是 SQLite 本身，只支持 SQLite 这一个数据库。它的 API 是同步的：打开连接、执行语句、读取结果都在调用线程内完成。

版本与稳定性：

  • v22.5 引入，早期需要 --experimental-sqlite；
  • v23.4 / v22.13 起不再需要该 flag，仍是实验特性；
  • v25.7 起成为 release candidate（Stability 1.2）。

因为它会阻塞事件循环，而 SQLite 本身很轻量，在大多数项目里感知不到；但如果你的服务并发很高、或者会跑耗时的查询，就要留意这一点。

建表

db.exec() 用于执行一段 SQL 语句，可以一次写多条（用分号分隔），但不接受参数绑定。

使用

参数绑定

db.prepare(sql) 返回一个语句对象，占位符有两种写法：

  • 匿名占位符 ?，参数按位置传入；
  • 命名占位符 :name、@name、$name，参数传对象，例如 stmt.all({ email, password })。

语句对象的常用方法：

  • run(...params)：执行写操作，返回受影响的行数和最后插入的 rowid；
  • get(...params)：返回第一行，没有结果时返回 undefined；
  • all(...params)：返回对象数组；
  • iterate(...params)：返回迭代器，适合结果集较大的场景；
  • close()：不再使用时释放语句，常驻的单例语句可以不关闭。

绑定的值只支持 null、number、bigint、boolean、string 和 TypedArray；传 Date 或普通对象会直接抛错，需要自己转成字符串或数字。

什么时候不适合用它

node:sqlite 是驱动而不是 ORM，选型时要清楚它不提供什么：

  • 只支持 SQLite，没有跨数据库的抽象；
  • 没有模型定义、类型推导和迁移工具，表结构变更要手写 SQL；
  • 要求 Node.js 22.5+；
  • API 全部同步，会阻塞事件循环。

如果项目需要跨多种数据库、或者希望用模型 / 迁移 / 自动补全来管理表结构，那么 Prisma 这类 ORM 更合适；如果只是连一个 SQLite，node:sqlite 零依赖、无代码生成，是更轻的选择。
