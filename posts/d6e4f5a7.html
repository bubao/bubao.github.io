Nginx 工程实践 -- 7. HTTPS 与证书

把 TLS 终止在 Nginx，是现在绝大多数部署的默认形态：浏览器与 Nginx 之间走 HTTPS，Nginx 与后端之间走内网 HTTP。这样证书只需要在一处签发和续期，后端服务不必各自实现 TLS，协议策略、HSTS、OCSP 也能统一收口。

flowchart TD
    C["浏览器"] -->|"TLS 握手
SNI + ALPN"| N["Nginx
TLS 终止"]
    N -->|"校验"| V["证书链
主证书 → 中间证书 → 根"]
    N -->|"HTTP 内网"| B["后端服务"]

一、证书文件的准备

Nginx 的 ssl_certificate 接受 PEM 格式文件，如果证书链不只有一张证书，需要把多张证书按顺序拼在同一个文件里：主证书在前，中间证书（CA）依次在后。顺序反了会导致握手时链校验失败。

私钥文件权限建议收紧（chmod 600），并确保 Nginx worker 用户可读。

二、最小可用配置

几个要点：

  • listen 443 ssl; 是新版写法；旧版 ssl on; 指令已废弃，不要再写；
  • 跳转用 return 301，不要用 rewrite ^(.*)$ https://...，前者不重新匹配 location；
  • $host 取的是 Host 头/请求行的主机名（不含端口），比 $server_name 更适合多域名；
  • 想让 HTTP 也响应 ACME 校验，就把 /.well-known/acme-challenge/ 单独放行，其余再 301。

三、协议与加密套件

  • ssl_protocols：按需保留 TLSv1.2 与 TLSv1.3；TLS 1.0/1.1 已被主流浏览器弃用，不必再开；
  • ssl_ciphers：默认值是 HIGH:!aNULL:!MD5，一般沿用即可；如需收紧，参考 Mozilla 的推荐套件列表；
  • ssl_prefer_server_ciphers on：由服务端决定套件优先级，通常建议开启；
  • ssl_ecdh_curve auto：让 OpenSSL 自动选择椭圆曲线；若使用 ECDSA 证书，要确保证书所用曲线在支持列表里。

四、会话复用：减少握手成本

完整 TLS 握手有额外往返，开启会话复用可以让老客户端"跳过"完整握手：

shared:SSL:10m 是所有 worker 共享的内存区（名称 SSL 可自取），10m 大约能存 4 万个会话。ssl_session_tickets 默认是开的，如果你更看重前向保密，可以关掉，只用共享 cache。

五、OCSP Stapling

客户端每次握手都要自己去 CA 的 OCSP 服务器查询证书状态，既慢又泄露访问行为。开启 stapling 后，由 Nginx 定期代查并把结果随握手发给客户端：

  • resolver 必须配，否则 Nginx 无法解析 OCSP 响应器域名；
  • ssl_trusted_certificate 指向包含中间证书的文件（fullchain.pem 即可），用于校验 OCSP 响应签名；
  • 验证：openssl s_client -connect example.com:443 -servername example.com -status，看到 OCSP Response Status: successful 即生效。

六、HSTS：让浏览器强制 HTTPS

  • max-age 是秒；建议先小值灰度（如 300），观察一段时间再放大；
  • includeSubDomains 会对所有子域生效，前提是所有子域都能提供有效 HTTPS，否则子域会不可访问；
  • preload 表示申请进入浏览器的内置 HSTS 列表，提交后基本不可逆（需数周甚至数月才能从列表移除），确认长期承诺再开；
  • add_header 记得带 always，否则错误响应上不会带这个头。

七、0-RTT：更快，但要想清楚

TLS 1.3 的 early data 允许客户端在第一个往返就带上请求数据，Nginx 用 ssl_early_data 开关：

风险：0-RTT 数据可能被重放。官方文档明确要求应用层用 $ssl_early_data 判断，只对幂等请求（GET 且无副作用）放行，写操作（POST/PUT/DELETE）应拒绝或要求完整握手。没有这层防护时不要开。

八、证书自动续期

以 certbot 为例，续期成功后触发一次 reload，而不是 restart：

  • nginx -s reload 会先做语法检查，再平滑替换 worker，不会断开已有连接；
  • 续期脚本要保证 ssl_certificate 指向的文件路径不变（软链或 --deploy-hook 里拷贝），reload 才能读到新证书；
  • 用 acme.sh 时同理，把 --reloadcmd 设成 nginx -s reload。

小结

  • 证书文件按「主证书在前、中间证书在后」的顺序拼成一个 PEM，私钥单独放并收紧权限；
  • listen 443 ssl; + ssl_certificate[_key] 是最小可用集；HTTP 用独立 server return 301 跳转；
  • 协议只留 TLSv1.2/TLSv1.3，套件沿用默认或按 Mozilla 推荐收紧；
  • 会话复用、OCSP Stapling、HSTS 是性能与安全的三个增量，按需逐个打开；
  • 0-RTT 只在后端能识别并拒绝非幂等请求时开启；
  • 续期后 nginx -s reload，不要 restart。
