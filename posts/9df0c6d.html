纯 Shell 跨平台组装 deb 安装包

本文揭秘 Debian 安装包的底层归档结构，介绍如何无需 Docker 与 dpkg 工具链，仅凭纯 POSIX Shell 在 macOS/CI 上秒级跨平台组装标准 deb 包。

在 Linux 桌面与服务器生态中，Debian 系发行版（如 Ubuntu、Debian、Deepin、统信 UOS）凭借庞大的用户基数，让 .deb 成为了软件分发最主流的标准载体。

然而在现代跨平台 CI/CD 流水线中，构建 .deb 安装包却常常面临尴尬的工具链断层：

  • 官方的标准打包工具是 dpkg-deb；
  • 但在实际团队开发中，CI Runner 可能是 macOS，本地开发机也可能是 Mac；
  • 为了打出一个 Linux 安装包，传统的做法往往是被迫在 CI 中启动一个沉重的 Docker 容器（拉取几百兆的 Ubuntu 镜像、挂载卷、执行 apt update 并调用 dpkg-deb），流水线耗时直接从几秒飙升到几分钟。

在开源博客工具 hpic 的跨平台发行体系中，我们通过剖析 .deb 的底层物理归档规范，实现了一套仅凭 POSIX 标准命令（tar 与 ar）跨平台组装合法 .deb 的极客方案：无需 root 权限、无需安装 Docker，在 macOS 本地不到 0.5 秒即可产出能在 Ubuntu 上直接双击或 apt install 顺利安装的标准安装包。

一、解密 .deb 包的物理归档本质

很多开发者误以为 .deb 是某种特殊的专有二进制格式，但其实它从设计之初就遵循 Unix 哲学的朴素理念：基于标准 Unix 归档工具拼接而成的复合包。

一个标准的 .deb 文件实际上就是一个 Unix ar 格式的归档文件，它严格且必须按以下顺序存放三个成员文件：

  1. debian-binary：一个纯文本文件，内容固定为字符串 2.0\n，声明该包遵循 Debian 2.0 打包协议；
  2. control.tar.gz：包含安装包元信息与维护脚本的压缩包；
    • control：包含 Package 名、Version、Architecture、Installed-Size、Maintainer 与依赖描述；
    • prerm / postinst（可选）：生命周期钩子，例如卸载前执行 pkill 退出正在运行的应用。
  3. data.tar.gz：待释放到目标操作系统中的文件树（遵循 Linux FHS 标准文件目录规范，如 /usr/local/bin、/usr/share/applications 等）。

只要我们严格按照规范生成这三个文件，并使用标准 ar 命令按顺序打包，产出的文件就和 dpkg-deb 构建出的产物在二进制结构上 100% 一致！

三、避坑关键细节剖析

虽然整体原理干净利落，但在跨平台运行（尤其是从 macOS 打包给 Linux）时，有几个高频踩坑点必须严格防范：

1. ar 归档文件的严格成员顺序

在 Unix 归档格式中，Debian 包管理器（dpkg / apt）在读取 .deb 时做的是流式扫描：

  • 归档内第一个文件必须是 debian-binary；
  • 第二个必须是 control.tar.gz；
  • 第三个必须是 data.tar.gz。如果顺序颠倒（例如写成 ar -rc out.deb data.tar.gz ...），dpkg -i 会当场报错 is not a Debian format archive。

2. BSD tar 与 GNU tar 的兼容性

macOS 自带的是 BSD 版本的 tar，而 Linux 默认是 GNU tar：

  • 在排除目录时，务必使用 --exclude='./DEBIAN'，避免将 DEBIAN 控制目录重复打包进 data.tar.gz；
  • 使用 -czf 默认采用通用 gzip 压缩算法，杜绝部分旧版本 dpkg 无法识别 zstd 压缩包的问题。

3. 权限必须预先规范化

  • prerm、postinst 等脚本必须在打包前执行 chmod 755，否则安装或卸载时系统会报 permission denied 无法执行；
  • 二进制可执行文件放入 /usr/local/bin 同样必须设为 755；
  • 图标与 .desktop 描述文件设为标准只读权限 644。

利用基础的 Unix 归档规范代替沉重的容器化方案，体现了“大道至简”的工程之美。一套十余行的纯 Shell 组装脚本，不仅彻底解除了对 Linux 宿主环境的依赖，也让桌面应用的跨平台自动化发布管道变得空前轻盈敏捷。
