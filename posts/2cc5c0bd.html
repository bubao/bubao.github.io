RK35xx 视频流水线：从硬解码到 NPU 推理

在 RK35xx 上做视觉项目，最终的帧率往往不是被 NPU 算力争夺的，而是被数据搬运拖垮的：解码出来的帧要不要拷给 CPU、缩放和格式转换谁来做、NPU 的输入从哪块内存来。RK35xx 把解码、2D 处理、神经网络推理、编码分别交给专用硬件，流水线的意义就是让数据在硬件之间流动，尽量少经过 CPU 和内存拷贝。

本文按数据流的方向讲清各模块分工、零拷贝链路的价值、多路并发的线程模型，以及常见的瓶颈定位顺序。

一、硬件模块分工

模块职责在视觉链路里的位置
VPU / MPP视频硬解码、硬编码入口：把码流变成原始帧
RGA2D 图形加速：缩放、格式转换、裁剪、旋转中间：把帧整理成 NPU 需要的尺寸与格式
NPU神经网络推理（RKNN 运行时）核心：目标检测、OCR、分类等
GPU通用并行计算（OpenCL/Vulkan）可选：复杂后处理、图像算法
CPU控制流、轻量后处理、业务逻辑贯穿：调度与结果处理

关键认知：这些模块是并行硬件，不是串联的软件层。设计目标是让它们同时工作，而不是让 CPU 在中间做接力。

二、数据流总览

每一步都在专用硬件上完成时，CPU 只做调度和轻量后处理；一旦某一步回落到 CPU（软解、软件缩放、逐像素拷贝），整条链路的帧率就会被这一步限制。

三、解码：为什么必须用 VPU/MPP

  • 软解的代价：H.264/H.265 解码是计算密集任务，ARM CPU 软解高分辨率码流会吃满核心，且功耗高；
  • 硬解的路径：码流直接送进 VPU，由 MPP（媒体处理平台）输出原始帧，CPU 几乎不参与；
  • 输出格式：解码通常输出 NV12 等 YUV 格式，后续 RGA 再转成 NPU 需要的 RGB/BGR 与尺寸；
  • 能力边界：可解码的路数、分辨率、码流格式以芯片官方数据手册为准，超规格使用会直接失败或掉帧。

四、RGA：把帧整理成 NPU 需要的样子

NPU 的输入要求通常很固定：特定分辨率、特定通道顺序、归一化后的数值。RGA 负责在硬件里完成：

  • 缩放：把解码分辨率降到模型输入尺寸，避免 CPU 逐像素插值；
  • 格式转换：NV12 → RGB/BGR，或通道重排；
  • 裁剪 / 旋转：ROI 提取、画面旋转，供特殊安装角度使用。

把预处理放在 RGA 而不是 CPU，收益是内存带宽：CPU 缩放需要读整帧、写整帧，而 RGA 是专用硬件，延迟和功耗都低一个量级。

五、NPU 推理与后处理

  • RKNN 运行时负责加载 .rknn 模型、准备输入输出内存、下发推理任务；
  • 后处理（解码检测框、NMS、坐标映射回原图、业务判断）通常在 CPU 完成，计算量相对推理很小；
  • 若后处理较重（如大量关键点、复杂图像算法），可考虑放到 GPU，但要先确认收益是否覆盖调度成本。

输入输出内存的布局、归一化参数要与模型转换时的配置严格一致，否则会出现「精度正常但结果全错」或「速度异常」的隐性故障。

六、零拷贝：省掉的不只是拷贝

在解码 → RGA → NPU 的链路上，最理想的状态是三者共享同一块物理内存，只用文件描述符（fd）传递，不做任何 memcpy。这就是零拷贝，常见载体是 DMA-BUF / DRM：

方案数据路径代价
拷贝式解码写缓冲 → CPU 读 → 写 RGA/NPU 输入多次内存读写，带宽翻倍
零拷贝解码缓冲以 fd 交给 RGA/NPU 直接访问需要驱动与运行时支持，编程复杂度更高

零拷贝的价值在高分辨率、多路并发时最明显：省下的带宽可以直接换成路数或帧率。落地时要注意缓冲区的生命周期与同步，避免出现花屏或读到半帧数据。

七、多路并发与线程模型

多路视频流的常见做法是每路一条处理线程，各自完成解码、RGA、推理、后处理，NPU 请求由运行时排队调度：

  • 解码路数受 VPU 能力限制；
  • 推理吞吐受 NPU 算力限制，多模型/多路共享同一 NPU 时需要排队；
  • 线程数不是越多越好，过多会在调度与内存带宽上互相拖累；
  • 瓶颈定位建议按链路顺序排查：解码是否满 → RGA 是否满 → NPU 是否满 → 后处理是否拖尾。

RK3588 的 NPU 为多核心设计，多模型并发时可由运行时分配核心；RK3566 这类单核 NPU 则更依赖请求合并与批量推理来提升利用率（细节见系列下一篇）。

八、常见瓶颈与排查

现象可能原因排查方向
帧率上不去某一路软解/软件缩放确认解码与 RGA 都走硬件
多路时整体卡顿NPU 吞吐不足、请求堆积减少路数、加大批量、错峰调度
内存持续增长缓冲区未复用、泄漏检查缓冲区池与释放时机
花屏 / 颜色异常格式转换遗漏、缓冲区不同步核对像素格式与同步点
结果坐标偏移缩放比例与坐标映射不一致核对 RGA 输出尺寸与原图映射

九、总结

  • 流水线的核心是让专用硬件做专用的事，CPU 只做调度与轻后处理；
  • 解码用 MPP、预处理用 RGA、推理用 NPU，是 RK35xx 视觉链路的标准分工；
  • 高分辨率、多路场景下，零拷贝是帧率的关键变量；
  • 排查瓶颈按「解码 → RGA → NPU → 后处理」顺序定位，避免盲目调参。
