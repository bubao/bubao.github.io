Express 项目环境搭建 -- 2. 跨域配置

浏览器里前端页面和 API 服务经常不同源，此时浏览器的同源策略会拦截 JS 读取响应，也就是常说的「跨域」。跨域不是请求没发出去，而是响应被浏览器扣下——所以解法在响应头上。

同源策略与预检请求

同源指协议、域名、端口三者完全一致。跨源时，浏览器分两种情况处理：

  • 简单请求：方法是 GET/HEAD/POST，且 Content-Type 限于 text/plain、multipart/form-data、application/x-www-form-urlencoded，又没有自定义请求头。浏览器直接发请求，只用响应头里的 Access-Control-Allow-Origin 判断是否放行。
  • 预检请求：不满足简单请求条件时（比如 Content-Type: application/json，或带了 Authorization），浏览器先发一个 OPTIONS 请求，询问服务端允许哪些方法、请求头、是否允许携带凭证；服务端应答后，浏览器再发真正的请求。预检结果可以用 Access-Control-Max-Age 缓存一段时间，避免每次跨域都多一轮往返。

常见坑

  • origin: "*" 与 credentials: true 不能同时使用；需要携带凭证时，要么写白名单，要么用 origin: true 反射请求来源（并补 Vary: Origin）。
  • 多个来源要按 Origin 动态判断，不能简单反射 *，否则任何站点都能带凭证打你的接口。
  • CORS 只是浏览器对 JS 读取响应的限制，服务端依然会处理所有请求，它不能替代鉴权。
  • 预检会额外增加一次往返，跨域接口多时可用 Max-Age 缓存，但缓存期内改配置不会立即生效。
  • 前置已有 Nginx 加过同名响应头时，Express 里就别重复设置，避免出现两个 Access-Control-Allow-Origin。
