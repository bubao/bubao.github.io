Express 项目环境搭建 -- 6. 代理静态资源

Express 可以通过中间件把某个路径映射到本地目录，对外提供静态资源。

常用选项

express.static(root, [options]) 支持一组控制缓存与响应行为的选项：

几点值得注意：

  • maxAge 接受字符串（"1d"）或毫秒数；带内容哈希的资源可以设长缓存，HTML 不宜过长，否则发版后用户拿不到新页面。
  • etag 让浏览器用 If-None-Match 校验，命中返回 304 Not Modified，省流量。
  • dotfiles 默认 ignore，请求静态目录下以 . 开头的文件不会命中；但敏感文件本来就不该放进静态目录。

与 Nginx 动静分离

Express 能发静态文件，但生产环境更推荐交给 Nginx：

维度Express 静态Nginx 静态
连接模型占用 Node 事件循环独立进程，事件驱动
缓存进程内、需自己配sendfile、expires、gzip 更成熟
职责静态与业务混在一起动静分离，Node 专注 API

典型结构是 Nginx 直接处理 /static/*，再把 /api/* 反向代理给 Node（可参考 Nginx 系列中 root/alias 与 proxy_pass 的几篇）。这样静态流量不消耗 Node 的连接数。

所以「不推荐」的准确含义是：高流量下别把 Node 当静态服务器用；小项目、内部系统直接用 express.static 完全没问题。
