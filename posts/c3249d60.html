CentOS 自定义动态 MOTD 欢迎信息指南

习惯了 Ubuntu 或 Debian 的同学在通过 SSH 登录服务器时，通常会被一段漂亮的系统概览信息所惊艳：系统负载、内存占用、磁盘空间、IP 地址一目了然。

这种登录提示在 Linux 中被称为 MOTD (Message of the Day)。然而在 CentOS / RHEL 等红帽系系统中，默认只提供了一个枯燥的静态 /etc/motd 文本文件。

本文将带你深入 Linux 的登录会话触发机制，不依赖臃肿的第三方包，手把手在 CentOS 上打造一套轻量、炫酷且实时更新的动态 MOTD 欢迎界面。

一、动态 MOTD 的实现机制

在 Linux 中，SSH 登录展示 MOTD 主要有两种技术路径：

  • Ubuntu / Debian 原生方案：内置了 update-motd 机制，在用户登录时通过 PAM 自动执行 /etc/update-motd.d/ 目录下的所有编号脚本，汇聚输出。
  • CentOS / RHEL 适配：CentOS 默认没有 Debian 移植版的 run-parts --lsbsysinit，但我们完全不需要拷贝数百行晦涩的兼容器代码，只需一段仅 10 行的 Shell 调度器 + PAM pam_exec 模块，即可完美复刻这一机制。

四、常见问题排查（FAQ）

Q1：配置完后登录没有看到任何输出？

  1. 检查脚本执行权限：/usr/local/bin/update-motd 和 /etc/update-motd.d/ 下的文件必须全部具备 +x 权限；
  2. 检查 /etc/pam.d/sshd 中是否遗漏了 stdout 参数；
  3. 手动执行 /usr/local/bin/update-motd，排查脚本是否存在语法错误。

Q2：为什么每次登录有轻微的延迟感？

如果采集脚本中包含了耗时较长的网络操作（例如 curl ifconfig.me 获取公网 IP），会导致 SSH 登录握手等待。

  • 优化建议：对于耗时的指标，可通过 Linux crontab 定时任务（如每 5 分钟执行一次）将结果异步写入静态缓存文件（如 /var/run/motd.cache），登录时只需毫秒级 cat 即可，保证零延迟秒进终端。
