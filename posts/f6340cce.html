泰山派 RK3566 离线 OCR 服务：tspi-ocr-web 实战

在边缘嵌入式开发板上部署深度学习应用时，往往受限于CPU 算力弱、内存容量小（通常仅 1GB ~ 2GB）、无独立显卡等瓶颈。如果在 RK3566 这类入门级嵌入式板卡上直接运行未经优化的大型 OCR 模型，往往会遭遇延迟高达数秒、内存频频 OOM、甚至导致板载系统假死的窘境。

为了解决低功耗嵌入式平台上的本地文字识别痛点，我开发并开源了针对立创·泰山派打造的高性能离线 OCR 服务项目：tspi-ocr-web。

本项目充分挖掘了 RK3566 芯片的硬件潜能，实现了 多引擎自动分级切换（RKNN NPU / NCNN NEON / ONNX），结合 Rockchip RGA 2D 硬件图形加速 与 零服务端绘图开销的纯前端标注 架构，整图识别耗时直接从数秒级压缩至 ~150ms。

💡 架构设计与核心思路

1. 三引擎智能分级与平滑回退

不同用户手头的模型格式和硬件驱动准备情况不同。项目通过全局配置 OCR_ENGINE=auto 实现了模型自动扫描与分级调度：

  1. 第一优先级（RKNN NPU 加速）：检测到 models/ocr/ppocrv4-rknn/ 下存在 det.rknn 与 rec.rknn 时，自动调用板载 0.8 TOPS NPU 执行硬件推理，耗时仅需 ~80ms；
  2. 第二优先级（NCNN NEON 极速引擎，开箱推荐）：搭载基于 PP-OCRv5 的移动端精简模型，深度启用 ARM NEON FP16 汇编级指令加速。模型总体量仅 11MB（识别模型仅 7.9MB），相比传统 90MB 的 ONNX 模型大幅节省 2GB 紧缺内存，推理耗时压制在 120~180ms；
  3. 第三优先级（ONNX 保底回退）：在无定制模型时自动回退到通用 ONNX 引擎，结合 RGA 硬件等比缩放，确保 100% 可用性。

2. 纯前端标注渲染：卸下服务端的绘图包袱

传统 OCR Web 服务在后端识别出文字框后，通常会在服务端使用 Python PIL / OpenCV 读取图片、解析字体、逐像素绘制矩形框和半透明文本标签，然后再对大图二次编码为 JPEG 返回。

在 RK3566 这类嵌入式 CPU 上，画图与大图重编码的耗时往往比模型推理本身还要耗时，且极易导致瞬时内存暴涨。

tspi-ocr-web 的优化方案：

  • 后端专注推理：API 仅返回纯净、轻量的 JSON 结构体（包含 8 点坐标 bbox、文本及置信度）；
  • 前端负责渲染：Web UI 基于 gr.AnnotatedImage 动态渲染组件，直接调用客户端设备（用户的浏览器/手机）的 Canvas 与 DOM 绘制交互式高亮线框与悬停标签。
  • 收益：板端服务端实现 零 CPU 画图耗时、零字体库常驻开销、零二次图像编码开销。

3. RGA 2D 硬件缩放与 DRM DMA-BUF 显存直通

在图像输入前处理（Padding、等比缩放、色彩空间转换）阶段，项目编写了 C 语言底层扩展 services/rga_helper.c，基于 Rockchip 官方 librga 的 c_RkRgaGetAllocBuffer + wrapbuffer_fd_t 实现 DRM DMA-BUF 连续物理内存分配，完美契合 Linux 6.1 内核标准，零 CPU 占用完成大图缩放。

结语与项目开源地址

在资源紧缺的嵌入式边缘设备上运行深度学习，核心思路是因地制宜、物尽其用：

  • 用 NCNN NEON FP16 / RKNN NPU 榨干计算硬件；
  • 用 RGA 分担图像格式转换与缩放计算；
  • 用 浏览器前端 Canvas 渲染 规避服务端低效的画图开销；
  • 全流程内存直通，杜绝磁盘 IO 磨损闪存。
