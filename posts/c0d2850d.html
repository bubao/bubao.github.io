Nginx 防盗链配置

搭博客或网站时，如果站内图片被外部高流量站点用 <img src="你的图片地址"> 直接引用，你的服务器就会白白为别人的页面出带宽和负载。这就是常说的盗链（Hotlinking）。

Nginx 内置的 ngx_http_referer_module 会检查请求头里的 Referer，用一个 valid_referers 白名单就能在网关层拦掉绝大多数外链，CPU 代价几乎为零。

一、工作原理

浏览器加载跨站图片时，会带上一个 Referer 头，说明"这个请求是从哪个页面发起的"：

valid_referers 定义合法来源；校验不通过时，内置变量 $invalid_referer 会被置为 1：

注意：Referer 是 HTTP 协议里就有的拼写（历史原因），配置里就照这个拼写写。

二、valid_referers 参数详解

参数含义建议
none允许没有 Referer 的请求建议加。直接访问图片 URL、下载工具、部分 Markdown/RSS 客户端不带 Referer，不加会把正常访问一起 403
blocked允许被代理/防火墙改写的、不以 http:// / https:// 开头的 Referer可视情况加，兼容内网代理
server_names自动把 server_name 里声明的域名全部加白建议加，省得手动列
*.mydomain.com通配任意多级子域名建议加，覆盖 www.、static. 等
*.baidu.com 等放行搜索引擎抓取可选。图片搜索/索引会回源访问，确认自己不在乎这部分流量再加

两点易错点：

  • 通配符 *.mydomain.com 不匹配裸域名 mydomain.com；好在有 server_names 时，server_name mydomain.com 已自动补上裸域名；
  • 白名单匹配的是 Referer 里的主机名部分，与协议（http/https）和路径无关。

三、生产级配置示例

几个实现要点：

  • if 在 location 里只用 return，是 Nginx 官方文档明确认可的少数安全用法之一；不要在里面做复杂逻辑（尤其别嵌套 if）。
  • error_page 403 + 精确 location = 的组合可以让拦截行为返回提示图而不会再次进入检测逻辑；网上常见的 rewrite ^/ https://...png break 要额外处理"提示图本身也被拦"的循环，不如这样清晰。
  • access_log ... conditional：当 $invalid_referer 为 1 时才落盘，配合 $http_referer 能在日志里直接看到是谁在盗链。
  • 想额外输出 no-transform 等头，标准 add_header 无法覆盖 expires 写入的 Cache-Control，需要 headers-more 模块（第三方）或只保留 expires。

五、局限与升级方案

Referer 防盗链的成本极低、维护简单，足以挡住"把图片链接贴进别的网页"这类最常见的滥用；但它不是访问控制：

  1. Referer 可伪造：curl -H "Referer: https://mydomain.com"、Python requests 都能轻易绕过。凡是能绕过最弱假设的方案，就不能替代鉴权；
  2. 只防"页面内嵌"，不防"下载后再分发"：知道 URL 的人总能拿到文件；
  3. 可能误伤正常场景：HTTPS 页面引用 HTTP 图片、某些 App/客户端不发 Referer、Referrer-Policy 策略会改变发送行为。建议先把被拦截日志开起来观察一两天再收紧白名单。

涉及付费资源或需要真正"防下载"时，按强度递增考虑：

  • secure_link（时间戳 + MD5 签名 URL）：链接带时效，过期即 410。Nginx 需要开启 ngx_http_secure_link_module（主流发行版默认包含）；
  • auth_request 动态鉴权：见本站 Nginx 静态资源鉴权；
  • CDN 签名 URL / 私有桶：把鉴权放到 CDN 或对象存储层。

一个最小 secure_link 例子：

服务端按 "过期时间+URI+客户端IP"+secret 生成 MD5，拼进 ?expires=...&sign=... 下发给浏览器即可。

六、参考资料

  1. Nginx 官方文档：ngx_http_referer_module — valid_referers / $invalid_referer 语法；
  2. Nginx 官方文档：ngx_http_secure_link_module — 签名防盗链；
  3. RFC 9110 §10.1.3：Referer；
  4. MDN：Referer 与 Referrer-Policy — 浏览器何时会发送/省略 Referer。

七、小结

  • valid_referers none blocked server_names *.你的域名 是最常用的起手式；
  • 拦截用 return 403 最稳；需要提示图时用 error_page + 精确 location，别用 rewrite 自循环；
  • 记得给被拦截请求单独 access_log，用日志确认没有误伤；
  • Referer 只能挡"懒"盗链，重要资源请上 secure_link / 鉴权。
