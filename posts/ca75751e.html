八、安全与加固建议

  • Token / Secret 视为密码：放 600 文件或密钥管理；不要进 Git；泄露后立即重置；
  • 加签优于关键词：关键词可被猜测，签名 + 1 小时时间窗更难伪造；
  • 通知里只放主机与来源元数据，不要带密码、Token、私钥路径；
  • 归属地 API 会把来源 IP 发往第三方，注意合规；内网来源（如 10.x）识别不出归属地是正常的；
  • 脚本被篡改风险低（root 700），但建议 shellcheck 过一遍；
  • 登录频率高时，考虑在脚本里按「用户 + 来源 IP」做短时间去重，避免刷屏。

九、附：zsh 报 no matches found

原文提到把脚本场景放进 .zshrc 时出现 no matches found:。根因是 zsh 对未加引号的参数展开会做通配匹配，变量为空时更容易触发；不只是脚本，任何 echo $var 都该加引号。

但治本的写法是：所有变量展开都加双引号（"$ip"、"$user"），优先用 $(...) 而不是反引号，并用 shellcheck 检查。
