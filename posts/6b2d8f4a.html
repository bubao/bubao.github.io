命令收口：统一项目的脚本入口

前面几篇分别讲了运行时、工具链、检查卡口和依赖，还有一个看似琐碎、实际很影响协作的环节：项目的各种命令——构建、测试、lint、格式化、数据库迁移、清理、发布。

它们常常散落在 README 的一段文字、CI 配置的一堆步骤、以及老成员的脑子里。新人不知道该敲什么；AI 编码助手也不知道——它只能猜，或者每次都要问你。

本文讲命令收口：用一个统一入口（Makefile / Task / just / npm scripts）把项目命令收敛成一组稳定、可发现、可被 CI 与 AI 复用的任务。它是「协作机制」板块的汇流点（hooks 与 CI 都调用它），下一篇本地开发与 CI 的一致性把它推向 CI 侧。完整导航见文末。

一、为什么需要命令收口

项目的命令，本质上是它对外暴露的「操作接口」，和 API 一样需要稳定、可发现。但它们经常处于「三不管」状态：

  • README 里一段：写了构建命令，但版本一升级就过期；
  • CI 配置里一坨：本地想跑，得去翻 workflow 文件，或者直接复制粘贴；
  • 老成员脑子里：新人只能靠问。

后果是：文档漂移、命令只在某些机器上能跑、新人上手慢、AI 每次都要重新猜。命令收口就是把它们收敛成仓库里的一个文件、一组固定任务名，让「怎么跑这个项目」变成可版本化的事实，而不是口头知识。

二、四种常见方案

方案形态优点局限
npm scriptspackage.json 的 scriptsNode 项目天然自带；零额外工具复杂逻辑与跨平台较弱
MakefileMakefileUnix 生态通用、资料多tab 缩进、Windows 支持差、语法老
TaskTaskfile.ymlYAML、跨平台、内置依赖/缓存/别名需额外安装一个二进制
justjustfile现代命令运行器，支持参数、环境、跨平台需额外安装一个二进制

选型不必纠结：

  • Node 项目：npm run <script> 起步，简单命令完全够用；
  • 跨语言 / 多工具链：Task 或 just 更顺手，YAML/类 make 语法，天然跨平台，本地与 CI 用同一份；
  • Unix-only 的库 / 工具：GNU Make 仍然是默认答案。

三、收口哪些命令

建议给每个项目定一组标准任务名，跨项目保持一致，降低认知与切换成本：

任务作用
dev启动本地开发服务
build构建产物
test跑测试
lint静态检查
fmt格式化
typecheck类型检查（有则）
clean清理产物
migrate / gen数据库迁移 / 代码生成（有则）

要点：

  • 命名统一：别一个项目叫 build、另一个叫 compile/package；
  • 可组合：build 依赖 test（用 deps 或 Makefile 的依赖），保证"构建前必测"；
  • 可独立运行：每个任务单独可跑，方便 AI 或 CI 精确调用；
  • 参数化：需要时支持环境变量/参数（如 task build APP=demo），而不是写死。

四、与 Hooks、CI、AI 的关系

命令收口不是孤立的整理工作，它是前面几篇的汇流点：

  • Hooks 调用它：pre-commit 里写 task lint，而不是把一长串命令塞进 hook 文件——命令逻辑只存在于一处；
  • CI 调用它：CI 步骤写 task test / task build，与本地同源，从根本上避免「本地能跑、CI 挂掉」（承接检查左移）；
  • AI 读它：把 Taskfile / Makefile 写进 AGENTS.md，AI 就知道这个项目该怎么跑，不用每次猜（承接 AI 上下文）。

换句话说：命令文件既是人的入口，也是 AI 的上下文，还是 hooks 与 CI 的共同调用目标。 一处定义，三处复用。

五、常见反模式

  • 命令只在 CI 里：本地要跑，得复制 workflow 步骤，容易漏。
  • README 命令过期：文档写 npm run dev，实际早改成了 pnpm dev。
  • 命名不统一：同一动作在不同项目叫不同名字。
  • 把复杂 shell 塞进 package.json：scripts 里几行尚可，逻辑一多就该换 Task/just/Make。
  • 没有统一入口：每个项目一套，跨项目无法迁移经验。
  • 命令写死、无法局部执行：想只测一个模块，却只能全量跑。

六、落地清单

  1. 选定一个入口：Node 用 npm scripts；跨语言用 Task 或 just；Unix-only 用 Make。
  2. 定义标准任务集并统一命名，写进仓库根目录。
  3. Hooks 与 CI 都调用这组任务，保证本地与 CI 同源。
  4. README 的「上手」部分只写入口（task / make 命令列表），细节交给命令文件。
  5. 把命令文件写进 AGENTS.md，让 AI 也能发现。
  6. 定期清理过期任务，保持「命令即事实」。
