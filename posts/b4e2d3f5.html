Nginx 工程实践 -- 5. 代理缓存 proxy_cache

反向代理天然处在上游服务的必经之路上，在这里加一层缓存，可以让重复请求不再打到后端：降低源站压力、缩短首字节时间、并在源站抖动时用旧数据兜底。本篇讲清楚 proxy_cache 的存储结构、缓存键、失效与击穿保护。

flowchart TD

proxy_no_cache?"}
    B -->|"是"| U["回源 upstream"]
    B -->|"否"| C{"缓存命中?"}

use_stale / cache_lock"]

一、缓存要解决什么

  • 源站压力：热点接口被反复请求，后端重复计算、查库；
  • 延迟：静态内容和"看起来静态"的响应，直接从磁盘返回；
  • 可用性：源站短暂故障时，用一份过期缓存继续服务，而不是直接 502。

它不解决"数据实时性"——缓存必然引入一致性问题，所以要先想清楚哪些接口可缓存、能容忍多久的旧数据。

二、缓存的层级

  • 浏览器缓存：Cache-Control / ETag，只对单个用户有效；
  • CDN：在离用户更近、规模更大的节点缓存，通常按 URL 全局共享；
  • 反向代理缓存：在源站前一跳，缓存粒度可控、能结合业务做 key 和失效；
  • 应用缓存：进程内或 Redis，处理更细粒度、更个性化的数据。

本节聚焦 Nginx 这一层。它适合缓存全局共享、更新不频繁、能容忍秒级到分钟级延迟的响应。

三、定义缓存区：proxy_cache_path

| 参数 | 作用 | | :— | :— | — | :— | | levels | 缓存文件的目录层级。1:2 表示两级，第一级 1 个字符、第二级 2 个字符，避免单目录文件过多 | | keys_zone | 共享内存区，格式 名称:大小。存缓存键和元数据，不存响应体；大小按 key 数量规划 | | inactive | 超过该时间未被访问的缓存会被清理，即使还没过期 | | max_size | 缓存区总大小上限，超出后由 manager 进程按 LRU 清理 | | use_temp_path | off 时直接写最终文件，省掉"临时文件 + rename"，通常更快 | | min_free | 保留的空闲空间 | | manager_* / loader_* | 管理进程和启动加载进程的频率/批量参数 | | purger_* | 主动清理（purger）相关参数，需配合 purger 能力 |

同一个缓存区可以在多个 location 复用；按业务/大小分开更利于排错。

五、什么时候不缓存

Nginx 默认会尊重上游的部分指令，不会缓存这些响应：

  • 上游带 Set-Cookie（默认不缓存，除非显式忽略）；
  • 上游 Cache-Control 含 private / no-store；
  • 请求方法不在 proxy_cache_methods（默认 GET HEAD）。

六、有效期与降级

  • proxy_cache_valid [code ...] time：覆盖上游给的有效期，适合统一缓存策略；
  • proxy_cache_use_stale：源站出现指定错误/超时时，先返回过期缓存；updating 表示"边回源边用旧缓存"，需配合 proxy_cache_background_update on；
  • proxy_cache_lock：同一个 key 只放一个请求回源，其余请求等待或读旧缓存，防止缓存失效瞬间大量请求同时打到后端（击穿）。

七、失效与 purge

  • 被动失效：inactive 到期、max_size 超限后由 manager 清理；
  • 主动 purge：标准版 Nginx 的 proxy_cache_purge 通常来自第三方模块（如 ngx_cache_purge），也有商业版内置；
  • 临时绕过：proxy_cache_bypass 让某个请求跳过缓存，用于调试或强制刷新；
  • 精确失效：按 key 删除文件较繁琐，更常见的做法是版本化 key——资源变更时改变 URL 或 key 前缀，让旧缓存自然过期。

八、观测：$upstream_cache_status

常见取值：

值含义
MISS未命中，已回源
HIT命中缓存
EXPIRED缓存过期，已回源
STALE命中过期缓存（配合 use_stale）
UPDATING正在后台更新
BYPASS主动绕过缓存
REVALIDATED通过条件请求重新验证

排查命中率时，先看 X-Cache-Status 的分布，再决定是 key 太细、min_uses 太高，还是 inactive 太短。

小结

proxy_cache_path 建缓存区，proxy_cache_key 定义"什么算同一条"，proxy_cache_valid / proxy_cache_use_stale 管有效期与降级，proxy_cache_lock 防击穿。缓存不是银弹：先确认接口可缓存、能容忍多大延迟，再决定 key 和失效策略；上线后用 $upstream_cache_status 观测命中率。
