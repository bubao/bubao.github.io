ADB 端口转发实现 SSH 连接 Android 设备

在 Android 开发、物联网（IoT）嵌入式板卡联调、车机系统定制以及 Termux 极客玩法中，我们最频繁使用的工具莫过于 adb shell。

然而，原生 adb shell 在面对复杂生产力场景时往往力不从心：

  • 终端体验简陋：不支持完整的 PTY 伪终端特性，在运行 htop、vim、tmux 或 Oh-My-Zsh 时经常出现退格键乱码、ANSI 颜色渲染异常或窗口大小（Resize）无法自适应；
  • 文件交互极其繁琐：无法利用成熟的 SFTP / SCP 客户端（如 FileZilla、Cyberduck、VS Code）进行图形化目录挂载与树状拖拽管理；
  • 难以融入现代化 IDE：无法利用 VS Code Remote-SSH 直接远程连入设备进行断点调试、代码补全与容器开发。

幸运的是，通过 ADB 端口转发机制（adb forward 与 adb reverse），我们无需依赖复杂的同一 Wi-Fi 局域网广播，只需一条 USB 数据线即可稳定建立一条高速、加密、支持全功能 Linux 开发环境的 SSH 隧道。

一、底层架构：ADB 正向转发 vs 反向转发

ADB（Android Debug Bridge）本质上由运行在 PC 端的 Client、Server 以及运行在移动设备上的守护进程 adbd 三层架构组成。

  1. 正向端口转发（adb forward）：在 PC 本地监听指定端口（例如 localhost:2222），所有流经该端口的 TCP 流量均由 ADB 协议封装，通过 USB 数据线传输至 Android 设备内部对应的端口（例如 localhost:8022）。
  2. 反向端口转发（adb reverse）：在 Android 设备本地监听端口，将设备发出的网络请求逆向回传给 PC 主机，特别适合 Android 端调用 PC 本地启动的测试后端 API 或 Mock 接口。

故障现象潜在根因解决思路
Connection refused设备端 sshd 尚未启动，或转发端口配置错误检查 adb shell ps -A | grep sshd；确认端口是 8022 还是 22
error: device unauthorized手机未弹出或未允许 USB 调试授权拔插 USB，在手机弹窗勾选“一律允许使用这台计算机进行调试”
Termux 连接经常无响应掉线Android 电池激进省电策略强杀了后台进程在系统设置中将 Termux 加入“电池白名单/无限制”，并在通知栏保持 Termux 唤醒锁（Acquire Wakelock）
Host key verification failed重新安装或更换设备后，原端口公钥记录冲突执行 ssh-keygen -R [localhost]:2222 清除旧密钥缓存

通过 adb forward 配合 OpenSSH，我们将 USB 数据线升华成了一条高带宽、低延迟的硬件开发总线。无论是移动端模型推理调试、自动化运维脚本执行，还是打造随身携带的口袋 Linux 服务器，这套方案都具备极高的实用价值与可靠性。
