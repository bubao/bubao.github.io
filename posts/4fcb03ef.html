升级 egg-socket.io 到 4.x

在企业级 Node.js 框架 Egg.js 的生态中，官方维护的实时通信插件 egg-socket.io 长期停留在 Socket.IO 2.1.1 版本。随着现代前端全栈技术的发展，现代客户端使用的 @socket.io/client 普遍已迈入 4.x 时代。由于 Socket.IO 在 2.x、3.x 与 4.x 之间经历了重大的协议重构（Engine.IO 协议版本升级），新版客户端直连老旧服务端时会直接触发握手异常（例如 Unsupported protocol version 或 CORS 拦截）。

既然官方插件长期未跟进维护，我们便可以在本地通过对插件源码进行“魔改”升级，将其核心升级至 Socket.IO 4.4.x 并配合全新的 @socket.io/redis-adapter 与 ioredis 实现分布式多节点集群广播。

一、为什么需要升级？（2.x 与 4.x 的核心断代差）

在动手改造前，我们需要明确升级的核心动力与破坏性变更（Breaking Changes）：

维度Socket.IO 2.x (老版插件)Socket.IO 4.x (本次目标)
底层协议Engine.IO v3 协议，包体体积大Engine.IO v4 协议，握手更轻量、长轮询开销更低
CORS 跨域默认全部放行允许跨域（隐患较大）默认遵循严格同源策略，需显式声明 CORS 配置
Redis 适配器使用已被废弃的 socket.io-redis采用全新官方驱动 @socket.io/redis-adapter
Redis 客户端依赖老旧 node-redis全面拥抱现代、高性能的 ioredis（支持主从、哨兵与集群）
广播与房间 API语法偏旧，异步支持不够优雅原生支持 io.except()、广播超时确认机制等高级特性

六、关键踩坑与排错清单（FAQ）

  1. 客户端报错：Error: server error: Unsupported protocol version

    • 原因：前端客户端使用的是 Socket.IO 4.x，但服务端仍是 2.x，两者的 Engine.IO 协议握手格式不兼容。
    • 解决：确保服务端按照本文升级至 Socket.IO 4.x，或在未升级前严格限定客户端使用 socket.io-client@2.x。

  2. 跨域拦截：Access to XMLHttpRequest at '...' from origin '...' has been blocked by CORS policy

    • 原因：Socket.IO 3.x 起默认彻底关闭跨域放行。
    • 解决：在服务端 config.io.cors 中显式指定 origin 与允许的请求方式。

  3. Egg 多进程集群下的广播失效

    • 原因：Egg 默认是多 Worker 进程模型，每个客户端可能连接在不同的 Worker 甚至不同的服务器节点上。
    • 解决：必须正确配置 config.io.redis。@socket.io/redis-adapter 会将广播消息推送给 Redis Pub/Sub，使所有 Worker 实例都能收到并转发给绑定的客户端。
