Rockchip 平台 librga 安装部署与权限问题排坑指南

在基于瑞芯微（Rockchip）芯片（如 RK3566、RK3568、RK3588 等）的嵌入式 Linux 开发中，多媒体与边缘 AI 处理有一条经典的高性能流水线：

$$\text{MPP (硬件编解码)} \longrightarrow \text{RGA (图像预处理)} \longrightarrow \text{RKNN (神经网络推理)}$$

  • MPP（Media Process Platform）：调用 VPU 硬件，对高分辨率视频流（H.264/H.265/VP9 等）进行低延迟解码，输出原始图像帧（通常为 YUV/NV12 格式）。
  • RGA（Raster Graphic Acceleration Unit）：调用专用 2D 硬件加速器，在零 CPU 占用下完成图像格式转换（如 NV12 转 BGR/RGB）、硬件缩放、居中裁剪及旋转，将图像尺寸与色彩空间对齐为模型输入要求。
  • RKNN：利用 NPU 硬件对预处理后的张量执行深度学习模型推理。

这两大硬件加速库在部署上有显著区别：MPP 没有官方预编译成品库，必须在本地或交叉编译环境中由源码构建；而 librga 仓库内置了各架构的预编译成品库，直接部署即可。

本文以 aarch64 平台（立创·泰山派 RK3566、野火鲁班猫等）为例，详细记录 MPP 的本机源码编译（包含低内存防 OOM 技巧）与部署、librga 的规范安装验证，以及普通用户调用 RGA 时 /dev/rga 权限拒绝的完整排坑与永久解决方案。

一、前置驱动节点检查

无论是使用 MPP 还是 RGA，均依赖内核底层对应的硬件驱动支持。在部署应用库前，请务必先检查设备节点：

1.1 检查 MPP 硬件驱动（VPU）

  • 若输出类似 crw-rw---- 1 root video ... /dev/mpp_service，说明内核 VPU 驱动已就绪。
  • 若提示 No such file or directory，说明当前固件内核缺少 MPP 驱动，硬件视频编解码将无法使用。

1.2 检查 RGA 硬件驱动

  • 若输出类似 crw-rw---- 1 root video ... /dev/rga，说明内核 RGA 驱动工作正常。
  • 若缺失此节点，多见于第三方的极简版 Armbian 固件，此时需更换官方标准发行版固件或为内核配置并编译 rkrga 模块。

二、Rockchip MPP 本机源码编译与部署

MPP（Media Process Platform）是瑞芯微官方的 VPU 编解码硬件库，仅负责视频编解码，与 NPU AI 推理独立：

  • 支持硬件解码：H.265 / H.264 / H.263 / VP9 / VP8 / MPEG-4 / MPEG-2 / MPEG-1 / VC1 / MJPEG / AV1
  • 支持硬件编码：H.265 / H.264 / VP8 / MJPEG
  • 官方仓库：https://github.com/rockchip-linux/mpp
  • 官方开发指南：仓库内 doc/Rockchip_Developer_Guide_MPP_CN.md

三、Rockchip librga 部署与配置

RGA（Raster Graphic Acceleration Unit）是 2D 图形硬件加速器，用于快速执行绘制、缩放、旋转、bitBlt、alpha 混合以及色彩空间转换（如 NV12 到 RGB/BGR），在图像预处理阶段性能远高于 CPU OpenCV 软转换。

  • 官方仓库：https://github.com/airockchip/librga
  • 官方开发指南：Rockchip_Developer_Guide_RGA_CN.md
  • 官方 FAQ：Rockchip_FAQ_RGA_CN.md

3.1 库类型说明

官方仓库自带各主流平台的预编译二进制文件，无需从源码重新编译：

  • librga.so（动态库，推荐）：应用开发、调试以及 Python 使用 ctypes 调用时必需。
  • librga.a（静态库，可选）：供 C/C++ 静态编译，Python 无法调用。

💡 环境准备建议：
若后续需在 Python 环境下通过 ctypes 调用 RGA（例如实现视频帧预处理并对接 RKNN 推理），建议配合独立的 Python 虚拟环境运行，避免污染或破坏系统环境。可参考前文：

六、总结

在 Rockchip 嵌入式硬件加速体系中：

  1. MPP 承担编解码重任，部署关键在本机编译的内存保护（修改脚本采用 -j1 单线程降并发防 OOM）；
  2. librga 承担 2D 硬件预处理重任，部署关键在利用官方预编译库快速归档规范；
  3. 权限机制不可忽视，配置 udev 规则可以一劳永逸避免生产/调试环境中因普通用户权限导致的 /dev/rga 调用崩溃。

两者结合，即可为后续的 RKNN 边缘 AI 推理提供高吞吐、零 CPU 瓶颈的底层多媒体加速支持。
