纯代码生成 DMG 视网膜背景

本文介绍如何利用纯 SVG 坐标计算与 macOS 原生 Swift 离线光栅化，零图形设计工具依赖自动化生成像素级对齐的 DMG 视网膜安装背景。

在 macOS 桌面应用的分发交付中，一个精致的 .dmg（磁盘映像）挂载视窗往往是用户接触软件的第一门面。标准的 DMG 引导视口通常包含：

  • 左侧应用程序图标（.app）；
  • 右侧系统 /Applications 文件夹替身链接；
  • 底部背景图中的图标定位底座虚线框、拖拽指示箭头以及使用提示胶囊。

然而在工程实践中，背景图的制作却长期困扰着开发团队：

  1. 坐标对齐极其脆弱：很多团队依赖设计师在 Figma / Photoshop 中手工画好背景图导出 PNG。然而，一旦在打包配置中微调了窗口尺寸或图标中心坐标，位图上的箭头和底座就会发生错位，只能反复找设计师手动修图；
  2. Retina 视网膜屏模糊：macOS 视窗坐标体系使用逻辑点（Points），若直接导出一倍图，在 Retina 高清屏下箭头和文字会发虚发糙；若导出的尺寸与配置不匹配，又会被拉伸变形；
  3. CI 自动化构建脱节：CI/CD 无头流水线中往往无法运行笨重庞大的商业图像处理软件，导致背景图只能作为静态二进制资产死板地存放在 Git 仓库中。

在开源项目 hpic 中，我们将“代码即图形（Code-as-Graphic）”的设计哲学延伸到了 DMG 背景图的构建上：利用 Node.js 动态计算 SVG 矢量坐标，并结合 macOS 内置 Swift/AppKit 实现零外部依赖的秒级光栅化。

一、架构设计：数学坐标驱动的渲染管线

背景图本质上是一组几何元素（背景矩形、文字标签、圆形底座、线性箭头、胶囊圆角）的有序排布。我们把 dmgbuild-settings.py 中的图标逻辑坐标作为单一输入，通过公式推导自动完成对齐：

三、破局：macOS 原生 Swift 零依赖光栅化

虽然 SVG 可以在浏览器中完美呈现，但 macOS DMG 的 .DS_Store 规范仅接受位图文件（PNG / TIFF / JPEG）作为背景图。

在本地开发机上，我们或许可以依赖 brew install librsvg 提供的 rsvg-convert 工具，但在纯净的 GitHub Actions macos-latest Runner 上，安装这些依赖需要消耗额外的构建时间。

我们发现了一个极为绝妙的系统级解决方案：利用 macOS 标配的 Swift 即时执行能力与 Cocoa / AppKit 框架，实现完全零外部依赖的离线光栅化。

原理解密：

  • macOS 的 NSImage 原生支持直接解析并绘制 SVG 矢量格式；
  • 通过 NSBitmapImageRep 在内存中开辟指定像素大小的位图画布；
  • 调用 rep.representation(using: .png) 直接输出标准的无损压缩 PNG 数据；
  • 全过程仅需调用系统自带的 /usr/bin/swift 命令，耗时不足 0.3 秒，完全免装任何第三方图形包！

五、总结

通过将 DMG 背景图全面代码化，我们获得了显著的工程红利：

  1. 像素级绝对对齐：告别肉眼修图与手动拼图，几何坐标就是排版的唯一定律；
  2. 免除设计软件负担：项目仓储中不再需要提交 PSD/Figma 等二进制草稿，全链路纯文本版本控制；
  3. 极速 CI 构建：借助 macOS 原生 Swift AppKit 光栅化通道，在没有安装任何外部转换工具的环境下依然能秒级生成高保真安装背景。
