RK3566 搭建 RKNN-Toolkit2 环境笔记

在基于瑞芯微 RK3566 / RK3568 等芯片（如立创·泰山派、Radxa、鲁班猫）进行边缘 AI 应用开发时，官方的 NPU 工具链主要基于 RKNN-Toolkit2。初学者在刚接触该生态时，极易对官方仓库中多个形态各异的包产生混淆。

在动手部署前，必须首先厘清三者的核心分工与运行位置：

组件名称运行环境主要职责与定位
rknn-toolkit2PC 端（x86_64 Linux）模型转换（ONNX/PyTorch/TF 转 .rknn）、量化、PC 端仿真、通过 USB/ADB 远程调试板端 NPU。严禁/无法在 RK3566 开发板上安装！
rknpu2RK3566 板端（aarch64）板端底层 NPU 运行时库，提供 C API（rknn_api.h）、动态库 librknnrt.so 及调试服务 rknn_server，用于 C/C++ 推理。
rknn-toolkit-lite2RK3566 板端（aarch64）板端专用的 Python 推理库，仅支持加载运行已转换好的 .rknn 格式模型，不具备模型转换与量化功能。

官方统一仓库地址：https://github.com/airockchip/rknn-toolkit2

本文将完整记录“PC 端转换环境搭建 $\to$ RK3566 板端驱动检查 $\to$ C++ 运行时部署 $\to$ 板端 Python lite2 推理环境配置”的端到端落地流程。

整体工作流概览

$$\begin{aligned}
\text{【PC 端 x86_64】}&: \text{ONNX / PyTorch 模型} \xrightarrow[\text{指定 target=”rk3566”}]{\text{rknn-toolkit2 转换与量化}} \text{.rknn 模型文件} \
&\quad\qquad\qquad\qquad\qquad\qquad\qquad\qquad\qquad\qquad\qquad\downarrow \text{拷贝至板端} \
\text{【板端 RK3566】}&: \begin{cases}
\text{C/C++ 工程} \longrightarrow \text{引入 rknn_api.h，链接 librknnrt.so} \
\text{Python 工程} \longrightarrow \text{通过 rknn-toolkit-lite2 加载并执行推理}
\end{cases}
\end{aligned}$$

五、与硬件加速流水线的衔接（MPP + RGA + RKNN）

至此，RK3566 平台上的视觉处理三大件已全部就绪：

  1. 环境准备：RK3566 Ubuntu26.04 安装 Python3.12 提供了隔离的多版本 Python 运行环境；
  2. 硬件编解码与预处理：Rockchip 平台 librga 安装部署与权限问题排坑指南 提供了 MPP 高速视频解码与 RGA 零 CPU 开销的格式转换与缩放；
  3. 边缘 AI 推理：本篇搭建的 rknpu2 / rknn-toolkit-lite2 负责接收 RGA 预处理完成的张量，直接送进 NPU 硬件完成高速神经网络推理。

六、常见踩坑与排障清单

  1. **试图在 RK3566 板端执行 pip install rknn-toolkit2**：
    • 报错无法找到符合架构的包。记住原则：转换在 PC（x86），板端只装 lite2 和 rknpu2。
  2. **板端运行报错 librknnrt.so: cannot open shared object file**：
    • 确认动态库已拷贝至 /usr/lib/ 或 /usr/lib/aarch64-linux-gnu/，且必须执行 sudo ldconfig 刷新系统链接器缓存。
  3. PC 转换的模型在板端初始化失败：
    • 检查 PC 端转换脚本中 rknn.config() 是否指定了 target_platform="rk3566"。若未指定或选错平台，生成的指令集与权重结构板端 NPU 无法识别。
  4. rknnlite 导入时报错版本不兼容：
    • wheel 包的文件名必须严格对应 Python 解释器的具体版本（如 cp38 对应 Python 3.8，cp312 对应 Python 3.12）。
  5. C/C++ 工程编译报错找不到符号：
    • 链接参数中需增加 -lrknnrt，并确保头文件目录包含 rknn_api.h。若在 PC 端进行交叉编译，请确认使用的是 aarch64-linux-gnu-gcc 交叉工具链。
