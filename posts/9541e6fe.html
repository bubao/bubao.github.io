构建多人开发的 Node.js 开发环境

Node 项目的环境不一致，往往从「版本」就开始了：Node 本体版本、包管理器版本、锁文件版本，任何一项不同，都可能让同一份代码在不同机器上跑出不同结果。

AI 编码助手会放大这个问题：它读不到你机器上的隐性约定，只能按通用习惯猜——生成的代码风格飘忽、装错依赖版本、绕开项目已有的 lint 与构建卡口。把版本、依赖、风格、提交这些约定写进仓库，既是给人看的规则，也是给 AI 的上下文。

本文给出一套可直接落地的 Node.js 开发环境配置，以 VSCode 为例，是「环境配置」板块的第一篇；同板块另有 Go 与 C/C++。文中版本号与工具状态截至写作时，具体以各工具官方文档为准。三篇配置篇之后，系列进入「协作机制」板块（AI 上下文 · 检查左移 · 依赖治理 · 命令收口），最后收敛到一致性与评审闭环。完整导航见文末。

一、统一运行时与工具链

1. Node 版本：版本管理器 + 仓库约定

多人协作的第一件事是统一 Node 版本。推荐做法是一个版本管理器 + 一个仓库内的版本声明文件：

  • 版本管理器任选其一：nvm、fnm、Volta、mise。团队统一选一个，不要混用。
  • 仓库根目录放 .nvmrc，写明项目使用的 Node 版本（建议写 Active LTS 的具体版本号，如 26.13.1）。成员进入目录后执行 nvm use（或 fnm 的 automatic）即可自动切换。
  • package.json 里用 engines.node 声明版本范围，作为机器上的硬性校验：

版本选择上，Node.js 官方建议生产环境只使用 Active LTS 或 Maintenance LTS。截至写作时，LTS 线包括 v26.13.1（Lithium）、v24.22.3（Krypton）、v22.23.5（Jod）；从 Node 27 开始发布周期改为年度发布，每个大版本在 6 个月 Current 加 6 个月 Alpha 之后都会进入 LTS。详见 Node.js Releases。

顺带一提：Node 22.18+ / 23.6+ 起内置的 TypeScript type stripping 默认开启，可直接运行只含「可擦除语法」的 .ts 文件；但它不读 tsconfig.json、不做类型检查，需要完整 TypeScript 支持（路径别名、类型检查）时仍要用 tsc 或第三方加载器。见 Node.js TypeScript 文档。

2. 包管理器：一个仓库只留一种 lock 文件

  • 团队统一包管理器（npm / pnpm / yarn 三选一），并在 package.json 用 packageManager 字段固定：
  • corepack 是 Node 自带的包管理器版本管理器，执行 corepack enable 后会按 packageManager 字段调用对应版本，避免「我机器上是 pnpm 8、你机器上是 pnpm 10」。
  • lock 文件必须入库（package-lock.json / pnpm-lock.yaml / yarn.lock），并且一个仓库只保留一种。混用多个包管理器会导致 lock 文件互相覆盖、依赖树不一致。

3. 环境变量：.env.example 入库，.env 不入库

  • 把需要配置的变量写成 .env.example（值为占位符）提交，成员复制为 .env 后自行填写。
  • VSCode 可装 DotENV 插件获得 .env 语法高亮。

二、统一编辑器配置（VSCode）

编辑器配置的目标是：保存时自动修复，提交前强制检查，让风格问题不依赖个人自觉。

插件

插件作用
ESLint（Microsoft 维护）实时展示 lint 规则违例，保存时自动修复
Prettier代码格式化（与 ESLint 分工，见下文）
Error Lens（可选）把报错/警告直接内联显示在行尾

分工原则：ESLint 管「规则」（有没有问题），Prettier 管「格式」（长什么样）。两者都开时，用 Prettier 官方的 eslint-config-prettier 关掉 ESLint 中与格式冲突的规则，避免保存时两边互相覆盖。近两年也有团队用 Biome 这类工具把 lint 与格式化合并为一个，可按团队情况选择。

四、汇总：新成员上手清单

把下面几件事写进 README，新同事照做即可：

  1. 安装团队约定的 Node 版本管理器，在仓库根目录执行 nvm use（读取 .nvmrc）。
  2. 执行 corepack enable，然后 npm install（自动安装依赖并注册 husky hooks）。
  3. 用 VSCode 打开项目，安装 ESLint、Prettier 插件；.vscode/settings.json 已随仓库提供。
  4. 之后正常开发：保存时自动修复，提交时自动跑 lint-staged 与 commitlint。

一句话总结：Node 的多人环境统一，本质是四份「仓库内的约定」——.nvmrc / engines 定版本，lock 文件定依赖，eslint.config.js + Prettier 定风格，husky + lint-staged + commitlint 定提交卡口。把它们写进仓库，环境就不再依赖某个人的机器。
